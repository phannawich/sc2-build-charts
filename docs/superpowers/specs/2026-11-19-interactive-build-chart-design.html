Interactive StarCraft II build chart

01 / How guides are built and published

Each guide defines its cards, positions, and directed connections. The build rejects duplicate card IDs within a guide and connections whose endpoints do not exist. archive/flowchart.png is a PvT transcription reference only; the site never loads or displays it.

Use Astro’s local server for development and preview. When the repository is ready to publish, GitHub Actions will build and deploy the static output to GitHub Pages. Configure Astro’s base for the repository path when publishing to a project site, and use it for internal links and asset URLs. Opening the generated pages directly via file:// is not required.

02 / Which guides ship

  1. First release · PvT
  2. Follow-ups · PvP and PvZ
  3. Optional · 2v2

The home page links to published guides only. Each guide has its own URL, starting with pvt/ under the site base. PvP and PvZ can reuse the same template when their charts are ready. The shared card-and-connection model does not assume a 1v1 matchup; a separate 2v2 layout is out of scope for the first release.

05 / What to check

  • Fidelity Compare every rendered card and arrow with the source.
  • Layout Check desktop and phone widths, including horizontal scrolling.
  • Controls Verify preview, pin, and clear with mouse, touch, and keyboard as applicable.
  • No JavaScript Disable JavaScript and confirm all cards and arrows remain visible.
  • Build validation Confirm duplicate card IDs and missing arrow endpoints cause the build to fail.
  • Hosting Preview the static build under the GitHub Pages base path. Check home-to-guide links, direct guide URLs, and assets. Confirm the site does not request the source PNG.

Until publication is explicitly requested, keep version history in local Git. Do not add a remote or push as part of this spec update.
